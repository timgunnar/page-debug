# page-debug 易用性设计

## 核心问题

用户报告测试失败后，Agent 需要执行一系列自动化步骤（注入断点、启动 CDP、连接浏览器），但这些步骤对用户是不可见的。如果用户在数秒内得不到反馈，会产生困惑：

- "排查开始了吗？"
- "现在能交互了吗？"
- "我能做什么？"

## 设计目标

1. **全程可见** — 关键阶段必须有用户可见的输出
2. **明确交接** — 从"自动化准备"切换到"交互式调试"时，有清晰的信号
3. **能力告知** — 用户进入交互模式时，明确知道可以要求 Agent 做什么
4. **持续引导** — 每轮交互结尾提示下一步可做的操作

## 解决方案

### 1. 后台启动，Agent 轮询就绪

断点注入器内部有 `while` 循环等待 `/close`，**必须后台运行**否则 Agent 无法交互。Agent 启动后台任务后，轮询 `/status` 直到就绪，然后将关键信息以启动模板通报用户。

断点注入器输出：

```
[page-debug] 检测框架: playwright_py
[page-debug] 在行 30 前注入断点...
[page-debug] 断点已注入 → E:\...\temp\_debug_test_xxx.py
[page-debug] 已生成 CDP conftest → E:\...\temp\conftest.py
[page-debug] 启动测试: python.exe -m pytest ...
[page-debug] 测试进程 PID: 10696
[page-debug] CDP 就绪: ws://127.0.0.1:9223/devtools/...
[page-debug] 已接管页面: https://www.baidu.com/
========================================================
  page-debug 浏览器桥接已就绪
  API: http://127.0.0.1:9234
========================================================
```

Agent 后台运行脚本 → 轮询 `/status`（最多 30 次，每次 1s）→ 得到 200 响应后提取页面信息 → 以启动模板通报用户。用户看到的是 Agent 整理后的结构化信息，而非原始终端输出。

### 2. 启动模板 — "你已进入交互模式"

桥接就绪后，Agent **必须先输出以下模板**再等待用户回复：

```
=== 交互式调试已就绪 ===

当前页面: https://www.baidu.com/s?wd=人工智能
页面标题: 人工智能_百度搜索
失败选择器: #22kw → 页面中不存在

你可以让我：
  - 检查某个元素是否在 DOM/可访问性树中
  - 执行 JS 查看元素属性、样式、位置
  - 查看控制台错误或网络请求
  - 手动操作页面（点击、输入、导航）

需要检查什么？
```

**模板的作用**：

| 元素 | 作用 |
|------|------|
| `=== 交互式调试已就绪 ===` | 视觉分隔线，明确告知阶段切换 |
| 当前页面 / 标题 | 确认复现成功，上下文可见 |
| 失败选择器状态 | 初步诊断结果，帮助用户理解问题 |
| "你可以让我" 清单 | 降低用户的认知负荷，不用猜测 Agent 能做什么 |
| "需要检查什么？" | 明确邀请用户输入，开启对话 |

**关键约束**：Agent 绝不可跳过此模板，即使用户之前已看过。

### 3. 逐轮交互，每轮引导

交互式调试是多轮对话，每轮遵循"执行 → 通报 → 邀请"三段式：

```
用户: 看看 #kw 在不在 DOM 中

Agent: [执行] #kw 存在于 DOM，是搜索输入框，值为"人工智能"。
      [邀请] 需要检查什么？

用户: 知道了，修复吧

Agent: [结束交互模式，进入修复]
```

**行为规范**：

- 每次回复结尾必须引导用户：如"需要检查什么？""还需要看别的吗？""要我修复吗？"
- 用户说"可以了""知道了""修复吧" → 结束交互，进入修复
- 不连续执行多个未请求的检查，等用户指令
- 执行用户请求的页面操作（输入、点击、导航等）后，页面状态已偏离断点。**主动提示用户可 `/reload` 恢复断点**，让用户知道有"后悔药"

**恢复断点示例**：

```
用户: 帮我点击第三条结果

Agent: [POST /click] 已点击第三条结果，当前页面: https://xxx/news/456
      页面已偏离断点，可随时让我 /reload 恢复。还需要看什么？

用户: 恢复吧

Agent: [POST /reload] 已恢复到断点页面: https://www.baidu.com/s?wd=人工智能
      需要检查什么？
```

### 4. 渐进式信息披露

Skill 的指令文件按信息密度分层，Agent 和用户按需加载：

| 层级 | 文件 | 内容 | 加载时机 |
|------|------|------|---------|
| 核心 | `SKILL.md` (~190行) | 工作流 + API 参考 + 交互协议 | 每次调用 Skill |
| 参考 | `references/failure-taxonomy.md` | 失败分类诊断表 | Agent 定位根因时 |
| 参考 | `references/layered-debugging.md` | 分层项目穿透追踪 | 遇到复杂项目时 |
| 文档 | `docs/design.md` | 架构设计 | 人类按需阅读 |
| 文档 | `docs/environment-decoupling.md` | 环境解耦 | 人类按需阅读 |
| 文档 | `docs/multi-framework.md` | 多框架适配 | 需要支持新框架时 |
| 文档 | `docs/usability-design.md` | 本文档 | 人类按需阅读 |

Agent 只加载前 3 层（~30KB），避免上下文膨胀。

### 5. 错误状态的显式反馈

当环境不满足时，Agent 主动指导用户：

```
Agent: 检测到未安装 playwright，正在安装...
       pip install playwright && playwright install chromium
       [安装完成后继续]
```

当框架不支持时，明确告知状态：

```
Agent: 检测到 Java/TestNG 项目。当前页面调试 Skill 对此框架的支持状态为"骨架"：
      - 断点注入可用
      - CDP 配置需要手动指定 browser launch 位置
      是否继续？
```

### 6. 前置检查清单

工作流第一步不是直接注入断点，而是确认环境就绪：

1. Python 3.8+ 可用，`playwright` + `websocket-client` 已安装
2. Chrome/Chromium 浏览器已安装
3. 防火墙允许本地端口 9223 和 9234
4. 被测项目依赖已安装

环境不满足时先指导用户完成安装，避免运行到一半报错。
